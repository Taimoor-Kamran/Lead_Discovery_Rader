# v0.2.0 — Source adapter contract + Google Places discovery

**Branch:** spec/v0.2.0-discovery
**Depends on:** v0.1.0 (merged, tag `v0.1.0`)
**Estimate:** 3–4 working days
**Blueprint refs:** §3 Data sources (slides 10–12, 16–18), §4 Background processing (slide 23), §5 discovered_records (slide 27), §8 Failure handling (slide 44)

## Goal
Running a search job actually discovers businesses. A job like `industry="plumber", geo={city:"Austin", state:"TX"}`
calls the Google Places API (New) through a pluggable adapter, and every result is stored as a
`discovered_record` with full provenance, cost tracking and retention metadata. This replaces the demo task from v0.1.0.

## Scope
- The `SourceAdapter` contract + adapter registry (blueprint slide 18)
- A shared outbound HTTP client for official APIs: timeouts, retry/backoff, `Retry-After`, per-source rate limiting, call metering
- `GooglePlacesAdapter` using **Text Search (New)** only, with a field mask, pagination and a per-job result cap
- `discovered_records` table (+ sightings per job run) and an `api_calls` table for cost tracking
- The `discovery` worker task wired into `POST /search-jobs/{id}/run`
- Retention: Places content expiry + a purge command (place IDs are kept)
- Daily call cap per source (cost guard)
- Read endpoints for sources, runs and discovered records
- A human-only live smoke command

## Out of scope
- Normalization, cleaning, the `businesses` table, dedupe (v0.3.0) — store raw only; `business_id` stays null
- Place Details calls (Text Search returns enough; Details adds cost)
- Any second source (Brave, Yelp, etc.)
- Area tiling to go beyond the per-query result limit (note it as a known limit)
- Website fetching or SSRF guard for arbitrary URLs (v0.4.0) — this spec only calls fixed Google hosts
- New frontend pages (v0.6.0) — test through FastAPI `/docs` and curl
- Scheduled/cron execution of the purge (v0.8.0) — a CLI command is enough here

## Human prerequisites
- Google Cloud project with **billing enabled** and **Places API (New)** enabled
- Create an API key restricted to *Places API (New)* only; put it in `.env` as `GOOGLE_PLACES_API_KEY`
- Set a **budget alert** in Google Cloud Billing (e.g. $20/month) before running any live search
- Check the current Places API (New) pricing: which SKU tier the chosen field mask falls into (phone and website fields usually cost more than basic fields). Adjust `PLACES_FIELD_MASK` if needed
- Check the current Google Maps Platform terms for how long Places content may be stored; set `PLACES_CONTENT_TTL_DAYS` accordingly (default 30). Place IDs may be kept
- Claude cannot do any of the above. Everything in this spec must be buildable and testable **without** a real key (all tests use recorded fixtures)

### Adapter contract (`adapters/base.py`)
```python
class SourceAdapter(Protocol):
    name: str                      # "google_places" — matches sources.name
    kind: SourceKind               # api | web | feed | licensed
    def discover(self, cfg: DiscoveryConfig) -> Iterator[Ref]: ...
    def fetch(self, ref: Ref) -> RawDoc: ...
    def validate(self, raw: RawDoc) -> ValidationResult: ...
    def normalize(self, raw: RawDoc) -> Candidate: ...      # light mapping only, no cleaning (v0.3.0 cleans)
    def emit_events(self, raw: RawDoc) -> list[Event]: ...  # returns [] for Places in MVP
    def get_rate_limit(self) -> RateLimit: ...
    def get_source_metadata(self) -> SourceMeta: ...
```
- `DiscoveryConfig`: `industry: str`, `geo: Geo`, `max_results: int`, `job_run_id: UUID`, `cancel_check: Callable[[], None]` (calls the v0.1.0 `checkpoint()`)
- `Ref`: `source_record_id: str`, `source_url: str | None`, `payload: dict | None` (Places returns full data in search, so `fetch` just wraps `payload` — no second API call)
- `RawDoc`: `source`, `source_record_id`, `source_url`, `payload: dict`, `fetched_at`
- `Candidate`: `display_name`, `formatted_address`, `phone`, `website`, `business_status`, `types`, `lat`, `lng` — all `Optional`, copied as-is, **never guessed**
- `RateLimit`: `requests_per_second: float`, `burst: int`, `daily_call_cap: int`
- `SourceMeta`: `display_name`, `terms_url`, `commercial_use_note`, `content_ttl_days`

### Google Places adapter
- Endpoint: `POST https://places.googleapis.com/v1/places:searchText` (confirm against current docs before merging; note result in Implementation notes)
- Headers: `X-Goog-Api-Key`, `X-Goog-FieldMask` = `PLACES_FIELD_MASK`, default:
  `places.id,places.displayName,places.formattedAddress,places.addressComponents,places.location,places.nationalPhoneNumber,places.internationalPhoneNumber,places.websiteUri,places.businessStatus,places.types,places.primaryType,nextPageToken`
- Body: `{"textQuery": ..., "pageSize": 20, "pageToken": ...}`
  - geo `{city, state}` → `textQuery = "<industry> in <city>, <state>"`
  - geo `{lat, lng, radius_m}` → `textQuery = "<industry>"` + `locationBias.circle {center, radius}`
- Pagination: follow `nextPageToken` until no token or `max_results` reached. `max_results` default 60, hard cap `PLACES_MAX_RESULTS_PER_JOB` (default 60). Record in Implementation notes if the API's own per-query limit is lower
- `source_record_id` = `places[].id`; `source_url` = `https://www.google.com/maps/place/?q=place_id:<id>`
- `validate`: parse with `schemas.py`; missing `id` → invalid; everything else optional
- The API key must never appear in logs, errors, `api_calls`, or stored payloads (redaction test)

### Shared HTTP client (`core/http.py`) — failure behaviour from blueprint slide 44
| Condition | Behaviour |
|---|---|
| Timeout / connection error / 5xx | Retry with exponential backoff + jitter, max 3 attempts, then `TransientError` |
| 429 | Honour `Retry-After` (cap 60 s), retry up to 3 times, then `RateLimitedError` |
| 401 / 403 | No retry → `AuthError` with a message that says "check GOOGLE_PLACES_API_KEY / API enabled / billing" |
| 400 | No retry → `AdapterError` with the API's error message (key redacted) |
| 2xx but schema invalid | 1 retry, then `SchemaError`; the bad body is stored on the job run error (truncated to 4 KB) |
- Every request (success or failure) writes an `api_calls` row via a metering hook
- Before each request: acquire a token from the per-source Redis token bucket; increment the daily counter and raise `QuotaExceededError` if `daily_call_cap` would be exceeded
- Default timeouts: connect 5 s, read 20 s

### Data model — migration `0002_discovery`
- `discovered_records`
  `id uuid pk`, `source_id fk sources`, `source_record_id text not null`, `source_url text`,
  `raw_payload jsonb null` (nulled on purge), `payload_hash text`, `business_id uuid null` (FK added in v0.3.0),
  `first_discovered_at timestamptz`, `last_discovered_at timestamptz`, `published_at timestamptz null`,
  `extracted_at timestamptz null`, `evidence_text text null`, `confidence numeric(4,3) null`,
  `content_expires_at timestamptz null`, `purged_at timestamptz null`, `created_at`, `updated_at`
  **unique (source_id, source_record_id)**; index on `content_expires_at`
- `record_sightings` — which run saw which record
  `id bigserial pk`, `discovered_record_id fk`, `job_run_id fk job_runs`, `search_job_id fk search_jobs`, `seen_at`, `rank int` (position in results)
  unique (`discovered_record_id`, `job_run_id`)
- `api_calls`
  `id bigserial pk`, `source_id fk`, `job_run_id fk null`, `endpoint text`, `status_code int null`,
  `attempt int`, `duration_ms int`, `error_class text null`, `created_at`; index on (`source_id`, `created_at`)
- Re-discovering an existing place **upserts**: update `raw_payload`, `payload_hash`, `last_discovered_at`, `content_expires_at`; add a sighting. No duplicate rows
- `content_expires_at = last_discovered_at + PLACES_CONTENT_TTL_DAYS`

### Worker task `run_discovery(job_run_id)`
1. Load the run + its search job; mark `running` (existing state machine)
2. For each `source_id` in `search_jobs.source_ids`: get the adapter from the registry (skip + warn if source disabled)
3. `discover()` → for each Ref: `checkpoint()` (cancellation), `fetch` → `validate` → upsert record + sighting; invalid records are counted, not stored
4. Update `progress_done` per record; `progress_total` = running count (unknown up front)
5. On finish: `done` with summary in the run (add `result_summary jsonb` column to `job_runs`: `{fetched, stored_new, updated, invalid, api_calls}`)
6. Errors map to the v0.1.0 retry policy: `TransientError`/`RateLimitedError` → retryable; `AuthError`/`QuotaExceededError`/`SchemaError` → fail immediately (no retry), clear message
7. Audit log entries: run started, run finished/failed, source enabled/disabled

### Endpoints (under `/api/v1`, cursor pagination, existing error envelope + RBAC)
- `GET /sources` — any authenticated role
- `PATCH /sources/{id}` `{enabled: bool}` — `admin`, `tech_admin`
- `GET /search-jobs/{id}/runs` — runs for a job, newest first
- `GET /jobs/{id}/records` — records sighted in a run (id, name, address, phone, website, status, first/last discovered)
- `GET /discovered-records/{id}` — full detail incl. `raw_payload`, sightings, provenance — `admin`, `reviewer`, `tech_admin`
- `POST /search-jobs` validation: reject a job whose `source_ids` contain an unknown or disabled source (422)

### CLI (`python -m app.cli …`, add Makefile targets)
- `sync-sources` — upsert registry adapters into `sources` (idempotent). `make migrate` runs it after Alembic
- `purge-expired` — set `raw_payload = null`, `purged_at = now()` where `content_expires_at < now()`; keeps `source_record_id`. Prints count. `make purge-expired`
- `places-smoke --industry plumber --city Austin --state TX --max 5` — **human-only live call**, prints a table, stores nothing. `make places-smoke`

## Acceptance criteria
- [ ] Running a search job with the Places fixtures stores 60 records from 3 pages and the run ends `done` with a correct `result_summary`
- [ ] Running the same job again creates **no new** `discovered_records`, updates `last_discovered_at`, and adds sightings for the new run
- [ ] Every stored record has `source_id`, `source_record_id`, `source_url`, `first_discovered_at`, `content_expires_at` (provenance test)
- [ ] Optional fields missing in the payload stay null in `Candidate` — nothing is guessed (test)
- [ ] `max_results=25` stops after 2 pages and stores exactly 25
- [ ] 429 with `Retry-After: 2` is waited out and the run succeeds; `api_calls` shows both attempts
- [ ] 500 three times → run retried per the v0.1.0 policy and finally `failed` with a readable error
- [ ] 403 → run `failed` immediately (no retries) with the "check key / API enabled / billing" message
- [ ] Exceeding `PLACES_DAILY_CALL_CAP` fails the run with `QuotaExceededError` before making the call
- [ ] Cancelling a running discovery stops it at the next record; already-stored records remain
- [ ] The API key string never appears in logs, `api_calls`, job errors or stored payloads (test with a sentinel key)
- [ ] `purge-expired` nulls `raw_payload` for expired records only and keeps `source_record_id`
- [ ] A `sales_rep` gets 403 on `PATCH /sources/{id}` and on `GET /discovered-records/{id}`
- [ ] No test makes a real network call (tests fail if respx sees an unmocked request)
- [ ] `alembic upgrade head` / `downgrade -1` succeed; the v0.1.0 model-registry test still passes
- [ ] `make check` passes
