# v0.4.0 — Website audit engine

**Branch:** spec/v0.4.0-website-audit
**Depends on:** v0.3.0 (merged, tag `v0.3.0`)
**Estimate:** 3–4 working days
**Blueprint refs:** §3 Website acquisition (slide 14), §6 Website audit (slide 34), §4 Background processing (slide 23), §8 Security (SSRF guard, slide 42), Failure handling (slide 44)

## Goal
Every business with its own website gets a **deterministic, evidence-backed audit** of its homepage:
reachability, HTTPS, mobile readiness, basic SEO tags, contact and booking options, e-commerce, tech
stack and PageSpeed. Each gap becomes a **finding** with verbatim evidence and a source URL, worded as an
observation ("Audit found no online booking link on the homepage"), never a verdict ("needs a new website").
Audits run automatically after resolution and can be triggered by hand. Everything is testable offline with demo sites.

Also carries three small items from v0.3.0 review: `make recompute-businesses`, a JWT secret length check,
and silencing the short-key test warning.

## Scope
- SSRF-guarded fetcher for arbitrary public URLs (the blueprint's "SSRF-guard everything")
- robots.txt check (cached) before any page fetch; per-host throttle
- Homepage-only deterministic audit (no crawling)
- PageSpeed Insights (mobile) via the existing `core/http.py` client, metered in `api_calls`
- Findings catalogue with evidence-based wording + service-category mapping
- `website_audits` table; audit retention
- `run_audits` worker task auto-enqueued after a resolution run; manual triggers
- Fixture fetch backend + ~10 demo sites so audits work with no network and no key
- Endpoints to read audits and filter businesses by finding
- `make recompute-businesses`, JWT secret check, test-key warning fix

## Out of scope
- AI summaries / classification / "most relevant service gap" (v0.5.0) — this spec is facts only
- JavaScript rendering (Playwright). JS-heavy sites are flagged, not rendered
- Crawling beyond the homepage + robots.txt; sitemaps; screenshots
- Logging in, submitting forms, or any interaction with a site
- Contact extraction for outreach (only presence of tel:/mailto:/form is recorded, not harvested lists)
- UI (v0.6.0)

## Human prerequisites
- In the same Google Cloud project: enable **PageSpeed Insights API** (free). Either add it to the existing key's API restrictions or create a second key restricted to it → `.env` `PAGESPEED_API_KEY=`. Without a key PSI still works at a low shared quota; the build and tests need no key at all
- Decide the bot contact URL or email shown in our User-Agent (e.g. the agency's site). Put it in `.env` as `BOT_CONTACT=` — polite crawling identifies itself
- Generate a strong JWT secret for any non-local environment: `openssl rand -hex 32`

### SafeFetcher (`core/safe_fetch.py`)
Every non-Google-API HTTP request in the app goes through this. Rules:
| Rule | Value |
|---|---|
| Schemes | `http`, `https` only |
| Ports | 80, 443 only (explicit other ports → refused) |
| DNS | Resolve host; refuse if **any** resolved address is private, loopback, link-local, multicast, reserved, unspecified, CGNAT (100.64/10) or IPv4-mapped equivalents (IPv4 + IPv6) |
| Redirects | Max 3; every hop is re-validated (scheme, port, DNS) |
| Size | Stream; stop at 2 MB (`truncated=true`) |
| Timeouts | connect 5 s, read 10 s, total 20 s |
| Content | Parse only `text/html`/`application/xhtml+xml`; others recorded, not parsed |
| TLS | Verify certificates. A TLS failure is a result (`tls_valid=false`), **never** retried with verification off |
| User-Agent | `LeadDiscoveryRadarBot/0.4 (+{BOT_CONTACT})` |
| Throttle | Per host: ≥ 5 s between requests (Redis lock); global concurrency `AUDIT_MAX_CONCURRENCY=4` |
| robots.txt | Fetched via the same guard, cached 24 h per host in Redis. Parse with `urllib.robotparser` for our UA token and `*`. 2xx → obey; 4xx → allowed; 5xx/timeout/network error → **disallowed** (RFC 9309, conservative) |
Known limitation (write in Implementation notes): DNS is validated before connecting; a hostile DNS server could in theory re-resolve between check and connect. Production hardening (egress proxy / pinned resolution) is a v0.8.0 item.

### Fixture backend (offline testing)
- `FixtureFetchBackend` answers only for hosts ending in `.invalid` (reserved by RFC 2606, can never be real) and only when `APP_ENV=development` or in tests
- Maps `host + path` → files in `backend/app/demo/sites/<host>/` (`index.html`, `robots.txt`, optional `_meta.json` with status code, headers, redirect target, TLS failure, timeout simulation)
- PSI calls for `.invalid` URLs are answered from `sites/<host>/psi.json` the same way
- Demo sites (≥ 10) must cover: modern HTTPS site with booking widget; old HTTP-only site with no viewport and `© 2016`; WordPress site with no meta description; Wix/Squarespace builder site; Shopify store; robots.txt disallowing `/`; robots.txt returning 503; a redirect chain http→https; an unreachable host (no fixture → connection error); a JS-shell page (tiny body, many scripts); a TLS failure. Map them onto the existing demo businesses' domains (e.g. `oakhillplumbing.invalid`)
- `expected_audits.json` lists, per demo domain, the expected status and finding codes — asserted by an integration test

### Deterministic checks (blueprint slide 34)
Each check returns `{value, evidence_text (≤ 300 chars verbatim), evidence_url}`; unknown stays `null`.
| Check key | How |
|---|---|
| `reachable`, `http_status`, `final_url`, `redirect_chain` | From the fetch |
| `https`, `http_redirects_to_https`, `tls_valid` | Final URL scheme; whether `http://` input ended on `https://`; TLS outcome |
| `viewport_meta` | `<meta name="viewport">` present, content captured |
| `title`, `title_length` | `<title>` text |
| `meta_description`, `meta_description_length` | `<meta name="description">` |
| `h1_present` | at least one `<h1>` with text |
| `tel_link`, `mailto_link`, `contact_form` | any `href="tel:…"`, `href="mailto:…"`, a `<form>` containing an email/tel input. **Store presence + one example, not a list** |
| `booking` | signature match in `fingerprints.py` (e.g. Calendly, Acuity, Square Appointments, Setmore, Housecall Pro, Jobber, ServiceTitan, Booksy, Vagaro, OpenTable, Mindbody) or a link whose text matches `book (now|online)`, `schedule (online|service|appointment)`, `request (a )?quote` |
| `ecommerce` | Shopify / WooCommerce / BigCommerce / Squarespace Commerce signatures, cart/checkout links |
| `social_links` | set of platforms linked (facebook, instagram, x, linkedin, youtube, tiktok, yelp, nextdoor, google) |
| `structured_data` | JSON-LD with `@type` LocalBusiness (or subtype) present |
| `favicon` | link rel icon present |
| `copyright_year` | highest 4-digit year (1995–current) found next to `©`/`copyright` |
| `tech_stack` | generator meta + signatures (WordPress, Wix, Squarespace, Shopify, Webflow, GoDaddy Website Builder, Weebly, Duda, Joomla, Drupal, React/Next.js hints) |
| `js_shell_suspected` | visible body text < 200 chars **and** ≥ 5 `<script>` tags |
| `psi` | mobile: performance score (0–100), LCP ms, CLS, TBT ms, CrUX overall category if present |
Fingerprints live as data in `fingerprints.py` (easy to extend), each with a unit test using a snippet.

### Findings catalogue (`findings.py`)
Each finding: `code`, `severity` (info/low/medium/high), `service_category` (`web_design`, `seo`, `booking`, `performance`, `ecommerce`, `security`, `web_presence`), `wording` template, `evidence_text`, `evidence_url`. Wording rule, enforced by a test that scans every template: must start with "Audit found", "Audit could not", "PageSpeed" or "Listing shows", and must not contain "needs", "should", "bad", "terrible", "outdated website".
| Code | Trigger | Service |
|---|---|---|
| `no_website` | business `website_kind = none` (no fetch) | web_presence |
| `social_profile_only` | `website_kind = social_profile` (no fetch) | web_presence |
| `unreachable` | network error / 5xx on final URL | web_design |
| `no_https` | final URL is http | security |
| `tls_invalid` | TLS failure | security |
| `no_mobile_viewport` | viewport missing | web_design |
| `missing_title` / `missing_meta_description` | absent or empty | seo |
| `no_h1` | no h1 | seo |
| `no_structured_data` | no LocalBusiness JSON-LD | seo |
| `no_online_booking` | booking false (only for industries in a config list where booking is normal: plumbing, hvac, electrical, dental, salon, auto_repair, legal, etc.) | booking |
| `no_contact_on_homepage` | no tel, mailto or contact form | web_design |
| `stale_copyright` | copyright year ≤ current year − 3 | web_design |
| `slow_mobile` | PSI performance < 50 (config) | performance |
| `js_shell_suspected` | flag, severity info — audit may be incomplete | web_design |
| `robots_blocked` | robots disallows us — audit not performed, severity info | — |
Example wording: `no_online_booking` → "Audit found no online booking or scheduling link on the homepage." with evidence `"No known booking widget or 'book online' link in {final_url}"`.

### Data model — migration `0004_website_audits`
- `website_audits`
  `id uuid pk`, `business_id fk businesses`, `job_run_id fk job_runs null`, `url_audited text`, `final_url text null`,
  `status enum[done, skipped, robots_blocked, unreachable, failed]`, `http_status int null`,
  `checks jsonb`, `psi jsonb null`, `tech_stack jsonb`, `findings jsonb` (array),
  `page_text text null` (visible text, ≤ 20 000 chars — input for v0.5.0 AI), `html_sha256 text null`,
  `rules_version text` (e.g. `audit-1`), `content_expires_at timestamptz`, `purged_at null`,
  `started_at`, `finished_at`, `created_at`
  Index `(business_id, created_at desc)`; GIN index on `findings` for filtering by code
- `job_runs.kind` gains `audit`
- `AUDIT_CONTENT_TTL_DAYS=90`: `purge-expired` also nulls `page_text` of expired audits (checks, findings, evidence snippets stay)
- Full HTML is **not** stored (hash only)

### Pipeline
- When `run_resolution` finishes `done`, enqueue `run_audits(parent_run_id)` (`kind=audit`, `params.parent_run_id`)
- It audits businesses linked or created in that resolution run whose latest audit is missing or older than `AUDIT_MAX_AGE_DAYS=30`, skipping `closed_permanently`
- `no_website` / `social_profile_only` are recorded as audits with status `skipped` and that finding, without any network call
- Idempotent within the max-age window; cancellable per business; progress counts; `result_summary` `{audited, skipped, robots_blocked, unreachable, failed, psi_calls}`
- A failure on one business never fails the run (it is recorded as that business's `failed` audit); the run fails only on systemic errors (DB/Redis down)
- PSI errors (quota, 5xx) leave `psi = null` with the reason in `checks.psi_error`; the rest of the audit still completes

### Endpoints (under `/api/v1`)
- `POST /businesses/{id}/audit` — enqueue a fresh audit now (ignores max age); roles `admin`, `tech_admin`, `reviewer`, `sales_rep`; idempotent via `Idempotency-Key`
- `POST /jobs/{id}/audit` — enqueue audits for a resolution run's businesses (`admin`, `tech_admin`)
- `GET /businesses/{id}/audits` — history, newest first
- `GET /website-audits/{id}` — full detail (checks, findings, PSI, tech); `page_text` only for `admin`, `reviewer`, `tech_admin`
- `GET /businesses` gains filters `finding=<code>` (repeatable, AND), `audit_status=`, and each item gains `latest_audit: {status, finding_codes, audited_at}`

### Carry-over items
- **`make recompute-businesses`** → `python -m app.cli recompute-businesses [--business-id ID]`: re-runs survivorship for every business (batched, idempotent, prints counts `changed / unchanged`). Needed whenever survivorship rules change on a live DB
- **JWT secret check**: at startup, if `APP_ENV` is not `development`/`test` and the JWT secret is < 32 bytes → refuse to start with a clear message; in development log a warning. `.env.example` shows `openssl rand -hex 32`
- **Test warning**: test fixtures use a ≥ 32-byte secret so `InsecureKeyLengthWarning` disappears from `make check`

## Acceptance criteria
- [ ] SafeFetcher refuses `http://127.0.0.1`, `http://10.0.0.5`, `http://169.254.169.254`, `http://[::1]`, `http://100.64.0.1`, a hostname resolving to a private IP, port 8080, `ftp://`, and a redirect from a public URL to a private one (tests)
- [ ] A robots.txt disallowing `/` → no homepage request is made, audit status `robots_blocked` (test asserts zero page requests)
- [ ] robots.txt 503 → treated as disallowed; 404 → allowed
- [ ] A TLS failure yields `tls_valid=false` and finding `tls_invalid`; no request is ever made with verification off (test)
- [ ] Response bodies over 2 MB are cut off and marked `truncated`
- [ ] Every finding has non-empty `evidence_text` and `evidence_url` (except `no_website`, which cites the business record)
- [ ] Every wording template passes the wording-rule test
- [ ] `no_website` and `social_profile_only` audits make zero network calls
- [ ] Loading demo data produces exactly the statuses and finding codes in `expected_audits.json`
- [ ] One business's audit crashing does not fail the run; its audit is stored as `failed`
- [ ] PSI quota error → audit `done` with `psi = null` and `checks.psi_error` set
- [ ] `GET /businesses?finding=no_online_booking&finding=no_https` returns only businesses whose latest audit has both
- [ ] `page_text` is hidden from `sales_rep` on `GET /website-audits/{id}`
- [ ] `purge-expired` nulls expired `page_text` only
- [ ] `recompute-businesses` fixes a business whose stored values disagree with current survivorship (test seeds the old Oak Hill mix)
- [ ] App refuses to start with a 16-byte JWT secret when `APP_ENV=production`; `make check` shows no `InsecureKeyLengthWarning`
- [ ] No test makes a live network call; `alembic upgrade head` / `downgrade -1` succeed; `make check` passes
