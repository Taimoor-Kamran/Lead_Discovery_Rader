**Branch:** spec/v0.1.0-foundation

## Goal
A running modular monolith: Docker Compose stack, FastAPI app with health check, PostgreSQL with
migrations, Redis + RQ worker, user auth with roles, the search-job model and job-status framework,
audit log, CI-ready `make check`. No data sources yet.

## Scope
- Monorepo layout from CLAUDE.md; `backend/` (uv), `frontend/` placeholder (Next.js app that renders a login page and calls `/health`)
- Docker Compose: `postgres:16`, `redis:7`, `api`, `worker`, `web`
- Config via Pydantic Settings; `.env.example`
- SQLAlchemy 2 models + Alembic migration for: `users`, `sources`, `search_jobs`, `job_runs`, `audit_logs`
- Auth: email + password (argon2), JWT access token (15 min) + refresh token (httpOnly cookie), RBAC
- Roles: `admin`, `sales_rep`, `reviewer`, `tech_admin`, `crm_manager` (blueprint slide 7)
- Job framework: enqueue RQ job, `job_runs` status `queued → running → done | failed | cancelled`, progress counts, retry with exponential backoff (max 3), cancellation flag, dead-letter = status `failed` + error text
- Audit log: append-only table written on every state change and every auth event
- Consistent error envelope + request ID middleware + structured JSON logging
- `make up`, `make down`, `make migrate`, `make seed-admin`, `make test`, `make lint`, `make check`

## Out of scope
- Any external API call, adapters, businesses table (v0.2.0+)
- Real UI beyond login + health page (v0.6.0)
- SSO, password reset emails, multi-tenant

## Human prerequisites
- Docker + Docker Compose installed on the dev machine
- Pick an admin email for `make seed-admin`

## Design
**Tables**
- `users(id uuid pk, email citext unique, password_hash text, role enum, is_active bool, created_at, updated_at)`
- `sources(id uuid pk, name text unique, kind enum[api,web,feed,licensed], config jsonb, enabled bool, created_at)`
- `search_jobs(id uuid pk, name text, geo jsonb, industry text, source_ids uuid[], status enum[draft,active,archived], created_by fk users, created_at, updated_at)`
- `job_runs(id uuid pk, search_job_id fk nullable, kind text, status enum, progress_total int, progress_done int, attempts int, error text, idempotency_key text unique null, cancel_requested bool, started_at, finished_at, created_at)`
- `audit_logs(id bigserial pk, actor_id fk users null, action text, entity_type text, entity_id text, before jsonb, after jsonb, created_at)` — no UPDATE/DELETE grants for the app role

**Endpoints** (all under `/api/v1`, Pydantic request/response models, RBAC dependency)
- `GET /health` (no auth) → `{status, db, redis}`
- `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`, `GET /auth/me`
- `POST /users` (admin), `GET /users` (admin), `PATCH /users/{id}` (admin)
- `POST /search-jobs` (admin, sales_rep), `GET /search-jobs`, `GET /search-jobs/{id}`, `PATCH /search-jobs/{id}`
- `POST /search-jobs/{id}/run` (idempotent via `Idempotency-Key` header) → enqueues a no-op `demo` job for now
- `GET /jobs/{id}/status`, `POST /jobs/{id}/cancel`
- Error envelope: `{"error": {"code": "string", "message": "string", "request_id": "string", "details": {}}}`
- List routes: `?limit=&cursor=` cursor pagination

## Implementation notes

Conservative choices made where the spec left room, recorded per CLAUDE.md rule 8.

**Job framework**

- `JOB_MAX_ATTEMPTS=3` means *three attempts in total* (the first try plus two retries),
  which is the stricter reading of "retry with exponential backoff (max 3)". After the
  third failed attempt the run ends `failed` with the error text stored.
- Backoff is `JOB_BACKOFF_BASE_SECONDS ** attempt`, so 2s then 4s with the defaults.
- The retry loop lives inside `execute_job_run` rather than being re-enqueued through
  RQ's scheduler: the MVP then needs no `rq-scheduler` process, and the backoff schedule
  is assertable in a test through the injectable `sleeper` argument instead of being
  waited out.
- Cancellation is cooperative. Handlers call `app.workers.tasks.checkpoint()` between
  units of work; that is the only place a run can be interrupted. A `queued` run is
  cancelled immediately by `POST /jobs/{id}/cancel`; a `running` run is flagged and stops
  at its next checkpoint, keeping the progress it had reached.
- `Idempotency-Key` is optional. Without it every call creates a new run; with it, a
  repeat returns the original run and does not enqueue a second one.

**Data model**

- `audit_logs` is append-only through a `BEFORE UPDATE OR DELETE` trigger as well as
  `REVOKE UPDATE, DELETE, TRUNCATE ... FROM PUBLIC`. Grants alone would not do it: the
  role the app connects as owns the table in development and in Compose, and an owner
  bypasses its own grants. The trigger binds everybody.
- `audit_logs` carries exactly the columns the Design section lists. Request correlation
  stays in the log stream, which already carries `request_id` on every line.
- `users.email` is `citext`, so addresses are unique case-insensitively; the migration
  creates the extension.

**Auth**

- The failed-login audit row is committed before the 401 is raised, because the request
  session is rolled back when an exception leaves a route.
- Login failures return one message for every cause (unknown email, wrong password,
  deactivated account) so the endpoint cannot be used to enumerate users.
- `require_role(...)` always admits `admin` in addition to the roles named.
- The refresh cookie is httpOnly and scoped to `/api/v1/auth`. `POST /auth/logout` always
  returns 204 so a stale session can always sign out.

**Pagination**

- Cursors are base64url over `(created_at, id)` and are treated as opaque; a malformed
  cursor is a 422 in the standard error envelope.

**Compose**

- Next's standalone server binds to `HOSTNAME`, which Docker sets to the container id, so
  the `web` image pins `HOSTNAME=0.0.0.0` — otherwise the container is reachable through
  the published port but not from its own health check on 127.0.0.1.
- Every entrypoint imports `app.models_registry`. The worker process only imports
  `app.workers.tasks`, and without the full registry SQLAlchemy cannot resolve
  `audit_logs.actor_id -> users.id`; `tests/unit/test_model_registry.py` guards this in a
  clean interpreter for each entrypoint.
- `CORS_ORIGINS` is annotated `NoDecode`: it is a comma-separated list in `.env`, and
  pydantic-settings would otherwise try to JSON-decode it before the validator runs.

**Tests and tooling**

- Integration tests run against a real PostgreSQL 16 started by testcontainers, because
  the schema uses citext, JSONB, arrays, native enums and a trigger. Redis is faked with
  `fakeredis`. If Docker is unavailable they skip with an explicit message rather than
  silently passing. No test contacts an external service.
- `migrations/env.py` calls `fileConfig(..., disable_existing_loggers=False)`; the default
  would silence the application's loggers whenever Alembic is driven in-process.
- pnpm is pinned to 10.20.0 through `packageManager`. pnpm 12 refuses to install while any
  transitive dependency has an unapproved build script, which cannot be resolved
  non-interactively.
